Ce qui a été construit, selon tes trois choix :
- Formulaires dynamiques : ils sont lisibles en GraphQL, par exemple formulaires(contenant: "RUCVSPEC1", derniers: 1) { rubrique(code: "…") }.
- Schéma étendu : INS, nom de naissance, adresse, médecin traitant, entourage, allergies, antécédents, prescriptions, observations par chapitre, transmissions ciblées, unités fonctionnelles du séjour. Migration V8.
- Format de liaison v3 : un #foreach ou un #if devient un seul content control qui contient texte, valeurs, boucles et conditions. Il est revalidé contre le schéma comme les autres liaisons.
- Données de test : trois patients fictifs alignés sur les gabarits (DUBOIS en SSR, ROUSSEL en cardiologie, BENALI en rééducation), avec dossier clinique et une instance de chaque formulaire. Migration V9, générée par un script : la relancer redonne le même fichier.

Changements de comportement existants à valider :
- Requête plus compacte. Les liaisons sont maintenant regroupées dans une seule requête par racine (patient, document). Sans ça, le 07 dépassait la limite anti-DoS du serveur, que j'ai gardée.
    - Conséquence : un document validé avant ce changement (ton demo) a ses données figées dans l'ancien format, que le nouveau plugin ne sait pas relire.
- Valeurs par défaut. L'auteur d'un document est désormais le signataire principal, et la date du document sa date de création, si elles ne sont pas saisies. Sans ça, « Lyon, le … » restait vide.
- RPPS transcodé. rppsTranscode renvoie maintenant le RPPS ; il renvoyait toujours null.
- Import de docx. Nouvel endpoint POST /api/documents/import pour importer un docx comme gabarit.

Limites :
- Le choix des éléments du multicontexte (quelle instance de formulaire, quelles observations) n'existe pas dans le POC. Le plus récent est pris, et les contextes sans titre exploitable affichent les 5 observations les plus récentes.
- Les images (signatures, logos, datamatrix INS) ne sont pas reprises.
- Quelques anomalies des gabarits d'origine sont signalées dans le rapport : variables de boucle utilisées hors de leur boucle dans le 17 et le 18, directives écrites #$foreach.
